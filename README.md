

# [MindMirror] AI 일기 자동화 시스템 최종 보고서

## 1. 자동화할 반복 업무 정의
**"일기 작성 리마인드 - AI 분석 및 시각화 - 미작성자 사후 케어"**
단순히 일기를 저장하는 것을 넘어, 정해진 시간에 작성을 유도하고, 작성된 내용을 AI가 요약·이미지화하며, 기록을 놓친 날에는 운세로 마음을 달래주는 통합 감정 관리 프로세스를 자동화합니다.

## 2. 자동화 도구 선정
*   **구글 폼:** 일기 입력 인터페이스
*   **구글 스프레드시트:** 데이터 저장 및 관리 (DB)
*   **Gemini API:** 일기 요약 및 운세 메시지 생성
*   **Apps Script:** 전체 시스템의 트리거 및 로직 제어

---

## 3. 핵심 워크플로우 (Trigger-Filter-Action)

사용자님의 시스템은 총 3단계의 자동화 시나리오로 구성됩니다.

### ① 시나리오 A: 밤 10시 작성 알림 (리마인드)
| 구분 | 내용 | 상세 설명 |
|:---:|:---|:---|
| **TRIGGER** | **매일 밤 10시 (시간 기반)** | Apps Script의 시간 기반 트리거가 작동 |
| **ACTION** | **알림 메일 발송** | 구글 폼 링크가 담긴 메일을 사용자에게 발송하여 작성을 유도 |

### ② 시나리오 B: 일기 작성 및 AI 분석 (실시간 처리)
| 구분 | 내용 | 상세 설명 |
|:---:|:---|:---|
| **TRIGGER** | **구글 폼 제출 (이벤트 기반)** | 사용자가 일기 작성을 마치고 '제출' 버튼을 누르는 순간 작동 |
| **ACTION 1** | **AI 한 줄 요약** | Gemini AI가 일기 내용을 분석하여 따뜻한 요약문 생성 |
| **ACTION 2** | **AI 이미지 생성/연결** | 일기 분위기에 맞는 이미지를 생성하거나 매칭하여 시트에 저장 |
| **ACTION 3** | **시트 데이터 업데이트** | 요약과 이미지 정보를 '나의 일기장' 시트 G열 등에 자동 기록 |

### ③ 시나리오 C: 미작성자 사후 케어 (익일 아침)
| 구분 | 내용 | 상세 설명 |
|:---:|:---|:---|
| **TRIGGER** | **다음 날 오전 9시 (시간 기반)** | 어제 일기 작성 여부를 확인하기 위해 트리거 작동 |
| **FILTER** | **어제 날짜 기록 확인** | **[조건]** 스프레드시트에 어제 날짜의 데이터가 있는가? |
| **ACTION** | **AI 운세 메일 발송** | **[결과]** 데이터가 없다면(미작성), AI가 생성한 위로의 운세 메일 발송 |

## 4. 데이터 흐름 다이어그램

```
[PM 10:00] ⏰ 트리거: "일기 쓸 시간이에요!"
      └─> ACTION: 리마인드 메일 발송 📧

[사용자] ✍️ 구글 폼에 오늘 하루 기록 및 제출
      └─> TRIGGER: 양식 제출 이벤트 발생

[AI 처리] 🧠 Gemini AI 가동
      ├─> ACTION 1: 일기 내용 따뜻하게 요약
      └─> ACTION 2: 일기 분위기 시각화(이미지) 및 시트 저장 📊

[AM 09:00] ⏰ 트리거: "어제 일기 썼나?"
      └─> FILTER: 시트 데이터 검사
            ├─ [작성 완료] -> 종료 (평온한 아침)
            └─ [미작성] -> ACTION: AI 위로 운세 발송 🍀
```

---

## 5. 구현 코드의 핵심 로직 (Apps Script)

*   **트리거 설정:** `sendReminderEmail`(밤 10시), `onFormSubmit`(폼 제출 시), `checkDiaryAndSendFortune`(아침 9시) 3가지 트리거를 통해 시스템이 멈추지 않고 순환합니다.
*   **필터링 기술:** `checkDiaryAndSendFortune` 함수 내에서 `for`문과 `if`문을 사용하여 어제 날짜의 데이터 존재 여부를 정확히 판별합니다.
*   **AI 통합:** `getAiSummary` 함수 하나로 요약과 운세 생성을 모두 처리하여 코드의 효율성을 높였습니다.

## 6. 기대 효과
1.  **강제성 없는 습관 형성:** 밤 10시 알림이 규칙적인 기록 습관을 만들어줍니다.
2.  **자기 객관화:** AI의 요약과 이미지를 통해 내 감정을 제3자의 시선으로 바라볼 수 있습니다.
3.  **심리적 안전망:** 일기를 쓰지 못한 날에도 비난 대신 AI의 다정한 운세를 받음으로써 긍정적인 마음가짐을 유지할 수 있습니다.

[MindMirror] AI 일기 자동화 시스템 (Make 버전) 및 도구 비교 보고서
1. 자동화할 반복 업무 정의 (동일)
매일 밤 일기 작성 리마인드, 작성 시 AI 요약 및 시각화, 미작성 시 다음 날 아침 AI 운세 발송을 통한 통합 감정 케어 시스템.

2. 두번째 자동화 도구 선정: Make (No-Code 플랫폼) 사용후 후기 
시각적 워크플로우: 트리거와 액션이 아이콘으로 연결되어 흐름을 한눈에 파악 가능.
빠른 연결: API 코드를 직접 짜지 않아도 클릭 몇 번으로 Google 서비스와 Gemini 연결 가능.
직관적인 필터 설정: 데이터가 지나가는 통로에 조건을 거는 방식이 매우 직관적임.

4. Make 워크플로우 구성 (Scenario)
Make에서는 총 3개의 **Scenario(시나리오)**로 기능을 분할하여 구현합니다.

① 시나리오 1: 밤 10시 알림
Trigger: Schedule (Every day 22:00)
Action: Gmail (Send an Email) - 구글 폼 링크 발송
② 시나리오 2: 일기 작성 및 AI 요약
Trigger: Google Forms (Watch Responses) - 새 응답이 들어오면 즉시 실행
Action 1: Gemini (Create a Completion) - 일기 요약 생성
Action 2: Google Sheets (Update a Row) - 시트 G열에 요약값 업데이트
③ 시나리오 3: 미작성자 운세 발송 (핵심 로직)
Trigger: Schedule (Every day 23:00)
Action 1: Google Sheets (Search Rows) - 어제 날짜의 행이 있는지 검색
Filter: [데이터 수(Total number of bundles)가 0인가?]
Action 2: Gemini (Create a Completion) - 운세 생성
Action 3: Gmail (Send an Email) - 운세 메일 발송
4. [비교 분석] Google Apps Script vs Make
사용자님이 느낀 **"편리함"**과 **"확장성"**의 차이를 표로 정리했습니다.

비교 항목	Google Apps Script (Code)	Make (No-Code)
초기 난이도	코딩 지식 필요 (상대적으로 높음)	드래그 앤 드롭 (매우 낮음/편리함)
구축 속도	코드 작성 및 디버깅 시간 소요	몇 분 안에 시나리오 완성 가능
확장성	매우 높음. 함수를 분할하고 재사용 가능	시나리오가 복잡해지면 선이 꼬여 한눈에 보기 힘듦
유지보수	용이. 로그 확인 및 특정 함수 수정이 빠름	에러 발생 시 어느 모듈의 문제인지 찾기 번거로움
배포 및 공유	매우 편리. 시트 복사 시 스크립트도 함께 복사됨	다른 사람에게 공유하려면 시나리오를 새로 세팅해야 함
비용	완전 무료 (구글 할당량 내)	무료 플랜은 실행 횟수(Ops) 제한이 있음
5. 사용자 인사이트 및 결론
💡 사용자 경험 분석
"Make를 처음 사용했을 때, 복잡한 코드 없이 연결되는 과정이 정말 편리하다는 느낌을 받았습니다. 간단한 자동화나 프로토타입을 빠르게 만들 때는 Make가 최고의 선택입니다."

🚀 업무 규모 확대에 따른 판단
"하지만 업무 사이즈가 커지면 Apps Script가 훨씬 유리하다고 판단합니다. 그 이유는 다음과 같습니다."

모듈화의 힘: Apps Script는 기능을 함수 단위로 쪼개 놓아, 특정 부분에 문제가 생겼을 때 해당 함수만 체크하면 되므로 디버깅이 훨씬 쉽습니다.
협업 및 배포: 구글 시트 자체에 코드가 내장되어 있어, 시트만 공유하면 다른 사람도 즉시 동일한 시스템을 사용할 수 있는 확장성이 강력합니다.
정교한 제어: Make의 필터보다 코드로 짜는 if-else 조건문이 훨씬 복잡하고 정교한 비즈니스 로직을 처리하기에 적합합니다.
